# Bounded native socket-address copyout

The Linux socket syscalls can report the full required address length after writing only the caller-supplied capacity. Previously getsockname/getpeername/recvfrom/accept passed the Darwin caller's buffer straight to Linux, then translated in place using that full reported length. A one-byte caller buffer surrounded by a larger original test envelope exposes trailing-canary corruption. Aliased native pathnames also can be longer than the final guest pathname, so this must be fixed before reversible UNIX root mapping.

Each wrapper snapshots/validates the guest capacity before a query, receive or accept; uses private512byte native storage; translates into separate private storage; and copies only min(original guest capacity, complete translated length). It reports the complete guest length through the output pointer. Null-address behavior for accept/recvfrom ignores the length pointer as before. Zero-capacity getters can query the needed length without writing bytes; negative lengths or non-null output with null length reject before consuming a message/connection. Unexpected native length>512 rejects without copying.

Reverse path conversion now rejects a guest pathname longer than104 bytes instead of shortening it, preserves full104byte length-bounded non-NUL output, and represents unnamed/no-source addresses without inventing a pathname. Apple public XNU confirms length-delimited UNIX paths need not be C strings (see unix-address-bounds.md). Existing Linux abstract-name semantics remain outside this pathname prerequisite; no general abstract-namespace fidelity is claimed. The accepted descriptor is closed only if it was created by this accept and subsequent conversion fails, before any flag inheritance; listener or unrelated descriptors are never closed.

`python3 darling/tests/qvolution/unix-output-bounds.py --mode MODE` compiles the actual current five production bodies and actual layout header under ASan/UBSan, with an explicitly synthetic kernel that honors write capacity and separately reports full length. MODE is getsockname/getpeername/recvfrom/accept/accept-error/reverse. The four wrapper modes cover capacities1..106, zero getters/null ignored source, non-null source+null length, preflight negative capacity, oversized native length, and zero-source recvfrom. accept-error validates close-only-new-descriptor ownership and no fcntl after failure. reverse checks103/104/105byte paths and unnamed header.
