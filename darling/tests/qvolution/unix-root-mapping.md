# Reversible long-prefix UNIX pathname mapping

The network conversion uses the existing canonical expanded path while it fits Linux sun_path. For an overlong in-root path it asks the actual server for the authenticated caller's canonical root and independently retained root FD, then passes /proc/serverPID/fd/rootFD + canonical guest suffix directly to the native syscall. Intentional outside-root paths are never redirected; unrepresentable aliases fail explicitly. The remaining full-path/basename limits are honest: this milestone makes short valid guest names work in long host prefixes, not all possible Darwin UNIX names.

Reverse conversion recognizes only the authoritative alias for the current caller root, with a component boundary and canonical suffix (no dot/dotdot/empty components). Re-expansion must match that same canonical root+suffix. Unknown /proc spellings, other roots and crafted symlink-resolution differences remain outside-root native addresses, never implicit guest roots. There is initially no root cache to invalidate after fork or vchroot change. Registry-owned descriptors outlive individual client processes. Canonical physical root rename mismatch fails honestly rather than fabricating identity; existing root-path semantics are not replaced.

Original unix-root-mapping.py compiles the actual conversion body/layout under ASan/UBSan with explicitly synthetic RPC and vchroot services. It creates only owned temporary roots. Full mode uses the actual native kernel for long-root bind/node/chmod/getname, one-byte caller capacity, distinct endpoints, forked sender with different local FDs, datagram and reverse name after sender exit. Source-only mode (QV_MAPPING_SOURCE_ONLY=1) runs alias/unknown-root/unknown-proc/canonical suffix/synthetic symlink mismatch and remaining-length vectors without sockets. Synthetic services are never a production RPC or guest pass.

Sandbox full mode returned EPERM at bind; no PID/namespace conclusion was established. Coordinator ran the exact full native test outside that restriction and it passed actual kernel mapping, with synthetic control-plane limits preserved. Source-only mode and actual registry/ABI tests also pass. The new original public unix-root-alias-guest.c is compiled, before-capable, and awaits coordinator staging: a45byte own directory prefix makes endpoint names47+bytes, forcing alias use in the measured68byte host prefix. It covers real getsockname/getpeername/connect/accept, post-sender-exit datagram source name, different client FD layouts, exact ordinary socket/chmod, small output canary, and an own relative symlink's existing canonical-name policy. No host API bridge or RPC stub exists in that guest fixture.

Prior incoming/output prerequisite regressions still run on actual source. Their synthetic services intentionally reject alias lookup because those tests qualify bounds/copyout, not mapping.

Production client helper and actual server objects compile isolated with generated candidate RPC headers. Combined guest long-prefix mapping, server lifecycle/root changes, cross-prefix delivery isolation, unchanged Foundation distributed-notification receive/send and unchanged Keka retake remain coordinator runtime gates. No publication, host default, shorter Keka prefix, unknown socket deletion, GPU or app qualification is claimed.
